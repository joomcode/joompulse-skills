# Benchmark against the competitor set

A head-to-head, parameter-by-parameter comparison of the seller's listings against the
competitors they actually face — showing where they win and, more usefully, where they lose.

## What to ask for

- **The seller's listings or store**, and their **shop or listing identifier**.
- **The competitor set** — from [discover-competitors.md](discover-competitors.md) if not
  already established.

**This analysis needs a connected store.** The parameter-level comparison draws on the
competitor-comparison data that only exists for a connected store. If the seller does not have
one connected, ask for the identifier; if it is unavailable, fall back to a public comparison of
their listings against the category and **say clearly which was used** — the public version is
coarser and should never be presented as the connected-store benchmark.

## Method

Compare the seller's listing against its competitor set on each parameter — price, shipping,
fulfilment, reputation, content, media — and sort the results into three bands:

- **Losing** — e.g. rated below every competitor, or no free shipping while nearly all
  competitors offer it → **mandatory fix**
- **Behind** — e.g. most competitors use fast fulfilment, or have a video → **scheduled fix**
- **Winning** — e.g. stronger reputation → **defend, and widen the gap**

Then rank the gaps **by impact**, not by how easy they are to fix. The cheapest fix is rarely
the one that moves sales.

## The score caveat — mandatory, every time

Whenever a comparison score is shown, state what it means:

> It is the **percentage of tracked competitors with a better value** — so **lower means the
> seller is ahead**, and higher means a bigger gap. It is relative to their competitor set, not
> an absolute grade.

This is not optional framing. A seller reading a low number as a bad grade will "fix" their
strongest parameter and leave the real gap untouched.

Where the data groups a listing into an overall band, present the band alongside the parameters
rather than instead of them — the band says how they are doing, the parameters say what to do.

## Procedure

1. Retrieve the per-parameter comparison for the seller's listing, including which parameter is
   weakest — that is the first fix.
2. Cross-reference the competitor set for context, and use the niche's typical values to show
   what "good" looks like here rather than in the abstract.
3. Rank the gaps by impact and band them mandatory, scheduled, defend.
4. Hand the content and quality fixes to
   [listing-optimization.md](listing-optimization.md), which turns gaps into concrete actions.

## Output

**Verdict first:** the single parameter costing the seller most, and what "good" looks like in
this niche.

Then the scorecard — one row per parameter, banded losing / behind / winning, with the niche
benchmark beside the seller's value. Follow with the prioritised gap list.

Show the score caveat wherever a score appears. State the estimate disclaimer once. Show `—`
for unavailable values.

## Boundaries

- **Requires a connected store** for the full analysis; label a public fallback as such.
- The comparison is **relative to the competitor set**, so it moves when the set moves. A
  parameter can improve because a competitor got worse — do not report that as the seller's
  improvement.
- Never present a relative score as an absolute quality rating.
- **Never claim a gap closed without a baseline** from before the change.
